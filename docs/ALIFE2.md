## 2. なぜ旧方式を延長しなかったか

ALIFE 23 の遺伝子は `plan = [親細胞, 角度, 種類, 接続長]` の列で、細胞を1個ずつ直接配置する。
この形式では「体節を1つ増やす」「脚を対で増やす」が数十個の遺伝子の同時変化を要し、描画も細胞の円を並べる以外にない。
上限が低いのは実装量ではなく符号化の問題と判断し、発生・物理・描画を別系統で書いた。

## 3. 設計上の決定

### 遺伝子：グラフ文法による間接符号化（`alife2-genome.js`）
- `parts`: 身体の一部の雛形（長さ・太さ・厚さ・筋肉・外皮・外骨格・関節可動域・局所リズム・器官）
- `links`: 「部品Aが部品Bをここに生やす」生成規則。対称性（なし／鏡像／放射n）、再帰回数 `repeat`、体軸上の発現窓 `lo..hi`、リズムの位相差を持つ
- 自己リンク（A→A）が体節の反復を作る。発現窓が「頭は先頭だけ」「脚は前半だけ」「尾は末端だけ」を決める（Hox 的）
- 「脚」「尾」「頭」という語はエンジン内に存在しない。規則が作った結果を観察者がそう呼ぶだけ
- 検討した他方式: 直接符号化（旧方式。却下）、遺伝子制御ネットワーク（表現力は高いが形態上限の実証に時間がかかるため後回し。文法の発現窓を濃度勾配に置き換える形で将来導入可能）

### 発生（`alife2-development.js`）
- 文法を幅優先で展開して体節の木（body plan）を作る。上限160体節
- `stage` 0→1 で芽から成体へ。後から生まれる体節ほど遅れて伸びる

### 身体物理（`alife2-physics.js`）
- 体節＝長さ一定の剛体棒。各体節は遠位端の質点1個を持ち、近位端は親の座標系に固定された点（質点の複素重み和）。付着が厳密で、運動量・角運動量を保存する
- 筋肉＝関節角への柔らかい拘束（XPBD）。力の上限は筋肉量×断面で決まる。子と親に等大逆向きに働くので、**筋肉だけでは重心は動かない**
- 水＝体節の横方向の動きに強く、軸方向に弱く抵抗する（抵抗力理論）。横抵抗は厚さ方向の面積に比例
- 底面＝押し付けられた接地パッドだけが摩擦を持つ。パッドが支えきれない体重は腹で引きずる
- **速度を与える変数は存在しない**

### 運動制御（`alife2-neural.js`）
- Phase 1 は関節ごとの局所振動子（振幅・位相・体節間の位相遅れ・打ち戻しの速度差・接地タイミングが遺伝子）
- `cmd = {drive, turn, heading}` が Phase 2 で脳が握る入力口。今は実験者が与える

### 描画（`alife2-render.js`）
- 各体節を先細りカプセルの距離場とし、同じ鎖の中は厳密な和、鎖どうしは滑らかな和で結合。これを厚みの高さ場として陰影・半透明化する
- 器官（筋繊維・消化管・神経索・生殖腺・眼）は同じ body plan から外皮の下に描く。体表の顆粒・環状紋は身体に固定された座標で生成
- スプライト・固定画像・種別ごとの描画コードは無い。5系統の違いは数値だけ
- 外皮は WebGL2（`alife2-gpu.js`、場の計算→陰影の2パス）で描く。同じ方式の CPU 実装が基準実装兼フォールバックで、Node 上でも画素を計算できるのでテストで描画を検証できる
- GPU 版だけの追加表現：クチクラの薄膜干渉色、2灯の反射。器官と体表構造は両方とも Canvas 2D

### 実験室の設計器（`alife2-bodyplan.js`）
- スライダーの値を遺伝子（文法）に書き換えるだけ。身体・運動・描画は進化個体と同じコードを通る

`docs/alife2/` に実ブラウザ（Chromium）で撮った画像がある。

- `sheet.png` — パラメーターの連続変化、発生段階、突然変異体
- `motion-tail-0..3.png` — 同一個体の連続する4時点（身体が変形している）
- `armored-blueprint.png` — 設計図表示、`lab.png` — 実験室全体

テスト（13件、全通過）が確認していること:
- 5系統は構造が互いに異なり、同じ遺伝子は同じ身体になる（遺伝）
- パラメーターで形が連続的に変わる。発生段階で体節が増える
- 変異した遺伝子は実際に発生し、物理が破綻しない
- **真空では関節が曲がっても重心は動かない**（全5系統、移動 < 1e-6）
- 筋肉ゼロ・活動ゼロでは進まない
- **脚があるだけでは歩けない**：パッド無し、または接地タイミングが合わないと速度は半分未満
- 打ちと戻しが時間対称な腕では泳げず、非対称にすると泳げる（放射型）
- 鰭の有無・波数で速度と移動コストが変わる
- 姿勢と形が変わると描画の画素が変わる

実測で分かった予想外のこと:
- 歩行の最適な接地位相は理論値（90°）ではなく 180° 付近だった。関節が指令に約1/4周期遅れるため。歩容は身体に合わせて調整される必要がある（＝進化・学習の対象になる）
- 放射型は底面を這う設定ではほぼ進まず、泳ぐ方が成立した。それでも 0.026 体長/s と遅い

## 5. Phase 2：代謝と世界（`alife2-organs.js` `alife2-engine.js`）

### 方針
複雑さ・大きさ・運動への報酬は一切無い。代わりに全部に値段を付け、身体によって違う生活が成り立つようにした。

| 仕組み | 効果 |
|---|---|
| 体表からの溶存栄養の吸収（表面積比例、局所的に枯渇） | 小さい身体の生活。密度に上限 |
| 粒状の餌（大きいほどエネルギーは体積比例、口の開きを超えると食えない） | 太い頭・大きい身体の生活 |
| 粒は移動する集中域に偏在。底面帯は流れが無く粒が固定 | 運動・感覚・接地の生活 |
| 一つの体節に入る組織量に上限（筋・消化・生殖・貯蔵・神経・輸送の合計 1.5） | 単体節は全部を少しずつ、多体節は部位ごとに特化 |
| 消化管から遠い体節は供給が落ち筋力が下がる。輸送組織で延ばせるが維持費がかかる | 大きい身体の内部構造 |
| 全組織・体表に体積／面積比例の維持費、筋仕事はエネルギー消費 | 無駄な器官は損 |
| 貯蔵量は体積と貯蔵組織に比例 | 大きい身体は飢えに強い |
| 出生時の大きさが遺伝子（大きい子は1匹あたり高い） | r/K 的な生活史 |
| 個体ごとの固定費（維持・複製） | 身体を無限に小さくできない |

### 進化試験が早期に暴いた設計の誤り（全部、実際に出た）
1. **幼体が永久に育たない**：成長1段の費用が幼体の貯蔵上限を超えていた → 成長用の積立を導入
2. **極小の吸収体が上限まで埋め尽くす**：個体数が資源ではなく人工の上限で頭打ちだった → 溶存栄養を薄くして資源律速に
3. **体積ほぼゼロの「塵」**：小さいほど維持費が消える → サイズ非依存の固定費を導入
4. **餌の配分の実装誤り**：エネルギー配分のつもりが個数配分で、小粒がほぼ無かった
5. **泳いで食う生活が最初から赤字**：人工の遊泳体を入れて収支を測ると、摂取が維持費の数十分の一だった → 粒のエネルギー密度を上げた
6. **出生が止まるとエネルギーが漏れる**（会計の不具合。保存則テストで発見）

### 生活様式の収支（人工個体を単独で 300 秒、`tools/alife2-lifestyle.js`）

|---|---|---|---|---|---|---|
| 原始個体（動かない） | 0.39 | 0.062 | 0.030 | 0.114 | +0.082 | 12/12 |
| 遊泳・眼なし | 1.47 | 0.241 | 0.030 | 0.244 | +0.026 | 7/12 |
| 遊泳・眼あり | 1.47 | 0.252 | 0.119 | 0.234 | +0.090 | 10/12 |
| 遊泳 2倍長・眼・顎 | 13.5 | 2.03 | 1.00 | 0.26 | −0.96 | 1/12 |
| 遊泳 3倍長・眼・顎 | 45.5 | 6.46 | 0.86 | 0.15 | −5.85 | 0/12 |

- **眼は元が取れる**：同じ身体で摂取が約4倍。旋回の符号を逆にすると盲目より悪い
- **大型化は不成立**：維持費は体積に比例して増えるのに、摂取はほぼ増えない。消費を一律に下げる解決はしていない

`docs/alife2/evolved.png` が終了時に多かった体制。**予想していなかった結果**：身体は多体節化したが動物にはならず、**口を複数持つ動かない捕食者**になった（seed 1 は口3〜4個の裂片状、seed 2 は口を最大64個並べた塊と柄のある形）。粒が沈降・拡散して勝手に当たるので、泳ぐより口を増やして待つ方が安い。固着性の懸濁物食者に相当する。

### 人工遊泳体の定着試験（`tools/alife2-invade.js`、変異なし）
原始個体の世界に眼のある人工遊泳体15匹を放つ。
- 小さく産む（出生段階0.3）：45匹まで増えるが、子は口が最小の粒より小さくて食えず、泳がない吸収体として停滞（速度 0.29 → 0.02）
- 大きく産む（0.7）：泳ぎ続けるが 23匹 → 4世代目で 2〜3匹

**結論：この経済では「泳いで食う生活」は存在はするが、待ち伏せ・吸収に競り負ける。** 動物が進化しないのは遺伝子構造の問題である前に、世界の側が動物を必要としていない。

## 6. 未解決の問題（正直な一覧）

1. **動く生活が勝てない。** 粒が勝手に流れてくる限り、待つ方が安い。必要なのは「動かないと届かない資源」と「動かないと死ぬ理由」：粒の沈降・拡散を弱めて集中域を速く動かす、捕食（固着者は食われる）、底面の固定餌を食い尽くす局所枯渇
2. **大型化が成立しない。** 維持費 ∝ 体積、摂取 ∝ 口幅×速度。世界のエネルギー流量も小さく、体積45の個体は全流量でも9匹しか養えない。相対成長（深部組織の低代謝、輸送網）と世界の規模の両方を設計し直す必要がある
3. **感覚が粗い。** 眼は「飲み込める粒の方向」を返すだけ。視野・距離・他個体の識別は無い。脳は 3×5 の線形写像
4. 幼体の口が小さすぎて親と同じ餌を食えない（出生時の大きさの遺伝子で回避可能だが、進化はまだ使っていない）
5. 有性生殖・捕食・死骸以外の個体間相互作用が無い
6. 世代が遅い：6000秒で16〜18世代、1シード約12〜14分。長期試験には高速化が必要（動く関節の無い身体は物理を省略済み）
7. 世界の体節上限は 64（計算量のため。実験室は 160）
8. 身体の自己衝突が無い（脚どうしが重なる）。関節可動域だけで防いでいる
9. 一部の変異体で関節が可動域を大きく超えることがある（長い体節＋強い力）
10. 平面2次元。放射相称動物本来の軸方向遊泳は表現できない。尾鰭は「縦に厚い板」として物理的には正しいが、上から見ると細い
11. GPU 描画はヘッドレス Chromium（ソフトウェア WebGL）での動作と画像しか確認していない。**実機 GPU での速度は未測定。** 現状は1体ごとに全画面を全体節で評価するので、多数個体の生態系では個体ごとの矩形描画に変える必要がある
12. 写実性：外皮の屈折、被写界深度、器官の立体感はまだ無い。目標画像の品質には届いていない
13. 放射型は8回の変異で約30%が体節数1/4未満に崩れる。他は0〜9%
14. 物理定数（筋応力、抵抗係数）は任意単位。現実の値との対応は取っていない
15. 旧 ALIFE 23 の生態系・神経回路・学習・営巣との接続は未着手
