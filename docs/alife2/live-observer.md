# 生態系ライブ観測・実況

2026-11-27。起点：`alife2-body-engine` の `5b03ec6`（v2.0.51）。ユーザー提供の v2.0.50 表示ログと ALIFE2 会話を参照した。ログの累計値を直近の変化として再利用してはいない。

## 使い方

`alife2.html` の右側に「生態系ライブ観測・実況」がある。60／300／1000シミュレーション秒を切り替え、個体数の時系列と収支、海域別の収支、系統・形態の増減を見られる。系統・形態のボタンや対象のある実況をクリックすると、個体、同じ体制、同じ系統の順に現存する代表を追う。代替先は同じ系統の代表であり、選んだ個体の直系子孫とは限らない。

観測は既定ON。読み上げと重要イベント時の世界記録は既定OFF。読み上げは重要な新着実況だけを対象とし、実時間30秒以上の間隔を置き、再生中は追加の発話を積まない。対応していないブラウザでは利用不可と表示する。

イベント世界はイベントを検出したステップの状態を直ちにJSON化し、実時間1分につき最大1件、直近2件だけメモリに持つ。保存ボタンから通常の世界ファイルとして出力できる。遺伝子・系譜も世界ファイルに含む。タブを閉じる前に出力すること。各島の一斉スナップショットではなく、表示中の島のイベント世界である。

通常の世界保存・自動保存・島ファイルには `ecosystemObserver` が付く。旧世界ファイルは新しい観測基準点から始められる。履歴だけのJSONと日本語テキストも出力できる。履歴JSON単体の復元は、対応する世界を同じ時刻・乱数状態で一時停止して行う。別の世界や経過後の世界に履歴を混ぜない。読み上げと自動スナップショットの有効状態は読み込み時にOFFへ戻す。

観測をOFFにした間は欠測とする。再開すると比較区間を分け、欠測を出生・死亡・移動と解釈しない。

## 何を数えるか

- 個体数収支：出生、餓死、老衰、傷による死亡、物理破綻、島への移入・移出、人為投入、その他の始祖追加。死産・上限による出生不成立は生存個体へ加えない。
- 海域収支：上記を実際の場所に記帳し、海域間の流入・流出を別計上する。死亡したステップで境界を越えた場合も、最終位置で死亡を記帳する。
- 増減：60秒以上の履歴を使い、個体数の15%以上かつ5匹以上の変化、系統・形態の1.5倍以上または半減かつ5匹以上の変化を候補にする。同一方向の同じ検出は300秒間抑制する。60／300／1000秒の実況には実際の集計秒数を付す。
- 世代継承：同じ体制を60秒前にも観測し、現存3匹以上、記録上3世代以上、観測期間に現存個体の最大世代が進んだ場合に「世代を越えて存続」と記録する。投入・人工個体・移入系統はこの自然継承の候補から除外する。優位性・将来の定着を証明したという意味ではない。
- 珍しい構造：20匹以上の世界で眼・関節を持つ形態が1〜2匹しかいない時の少数候補。新規性・有益性とは別。
- 実際の状態：エンジンが累積した回路出力の寄与、現在の視覚信号と配線、発声、遺伝した重みからの結合変化、同一個体の移動距離・摂食量の変化を読む。配線があることと有益な感覚利用を区別する。
- 発声：既存の減衰音声統計を読む。25回以上の鳴き声や、聞き手25例・6匹、鳴き手3匹以上など既存の検出条件を満たした行動との関連候補を報じる。音声の意味や通信の成立を断定しない。減衰統計を60／300／1000秒の正確な回数と呼ばない。
- 記録更新：観測開始後の個体数・最大体節数・最大世代。ロード前の全歴史の最高記録とは区別する。
- 消失：細かな体制の消失は累計集約。20匹以上・3世代以上続いた体制の消失は対象付きの重要実況にする。移出だけで島から消えた体制を死亡絶滅と呼ばない。他島での絶滅は判定しない。

実況のラベルは「観測事実」「相関」「仮説」を区別する。本実装は因果説明を生成せず、測定された変化と関連候補だけを自動生成する。餓死というエンジン分類から、餌の枯渇・維持費・幼体の摂食能力などの背景原因を決めつけない。

## 世界を変えない境界

`alife2-observer.js` は世界ごとの独立したノートをWeakMapに置く。`step`、`spawn`、`introduce`、`immigrate`、`emigrate` の呼び出しを透過的に包み、元の戻り値を返す。物理・遺伝・選択・乱数・エンジン本体のファイルは変更しない。世界の保存関数もそのまま残す。表示側とWorkerの保存・復元の入口だけが観測データを付加・読み出す。

観測ON時は毎ステップの既存個体配列を1回走査して海域移動・死因を記帳する。時系列は2シミュレーション秒間隔、実況検出は10秒間隔、UI更新は既存のパネル更新（実時間約1秒間隔）に合わせる。直近502標本・300実況、各標本の上位96系統／形態／体制まで。過去の集団は個体数と最大世代に圧縮する。履歴の無い集団は0と見なさず「?」とする。履歴は無期限の完全な研究データ記録ではない。

島Workerも同じノートを保持し、保存と島切り替えで履歴が世界について移る。Workerは直近3実況と各窓の要約だけを通常の状態通信に付ける。異なる島の時計を合算しない。もともとブラウザの島間移動は実行速度とメッセージ到着順に依存し、同seedでも再現可能ではない。観測による計算時間の増加で非同期の交換順が変わる可能性は残る。同一seed一致テストは同一ステップ・同一外部操作列の世界を検証するもので、非同期ブラウザ群全体の歴史一致を主張しない。

## 検証と引き継ぎ

`node --test tests/alife2-observer.test.js`：世界全体と乱数の一致、切り替え・保存復元、全海域の収支、投入・移入出、欠測、全時間窓、重複、移出のみの消失、人工由来の誤判定防止、Workerの起動・保存・切替を検証する。`node --test tests/*.test.js` で既存テストも確認する。

`node tools/alife2-observer-bench.js` は隔離した世界のコピーでON/OFFを交互に測る。描画・OS・ブラウザ音声の性能を代表するものではない。CPUを使う本番の世界とは同時に走らせない。

作業枝では版を上げない。push／PR後に公開枝の最新変更を取得し、統合して検証し、公開直前に `tools/alife2-bump.js` を一度だけ実行する。mainとPagesの公開結果を確認する。結果の確定値・PR・公開コミットは作業記録へ追記する。
